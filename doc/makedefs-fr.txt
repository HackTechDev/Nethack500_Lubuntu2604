NOM
       makedefs - fonctions diverses de NetHack utilisées à la compilation

SYNOPSIS
       makedefs { -o | -d | -e | -m | -v | -p | -q | -r | -h }

       makedefs --input fichier --output fichier --commande

DESCRIPTION
       Makedefs  est  un outil utilisé à la compilation pour créer et modifier
       divers fichiers sources de NetHack(6).  Pour des  raisons  historiques,
       makedefs  accepte  deux  sortes de lignes de commande.  Avec une option
       courte, les fichiers traités sont fixés à la compilation  de  makedefs.
       Avec  une  option longue, les options --input et --output indiquent les
       fichiers de la --commande.  Chaque commande n'existe que sous l'une des
       deux formes.

COMMANDES COURTES
       Les commandes courtes s'écrivent indifféremment  en  minuscules  ou  en
       majuscules.

       -o     Produire onames.h.

       -d     Produire data.base.

       -e     Produire dungeon.pdf.  Le fichier d'entrée dungeon.def passe par
              le  même  traitement  que  celui de la commande --grep ; voir la
              section FONCTIONS MDGREP plus bas pour les détails.

       -m     Produire date.h et le fichier options.  Seulement  s'il  existe,
              dat/gitinfo.txt est lu pour obtenir les informations githash= et
              gitbranch=,  et les #define correspondants du préprocesseur sont
              ajoutés au fichier date.h.

       -p     Produire pm.h.

       -q     Produire le fichier rumors.

       -s     Produire les fichiers bogusmon, engrave et epitaph.

       -1     Produire le fichier epitaph.

       -2     Produire le fichier engrave.

       -3     Produire le fichier bogusmon.

       -h     Produire le fichier oracles.

COMMANDES LONGUES
       --debug
              Afficher des informations de débogage.

       --make [commande]
              Exécuter une commande courte.  La commande s'écrit sans le tiret
              initial.

       --input fichier
              Indiquer le fichier d'entrée  de  la  commande  (si  elle  en  a
              besoin).  Si le fichier est -, l'entrée standard est lue.

       --output fichier
              Indiquer  le  fichier  de  sortie  de  la commande (si elle en a
              besoin).  Si le fichier est -, le résultat est écrit sur la sor-
              tie standard.

       --svs [séparateur]
              Écrire une chaîne de version sur la sortie standard, sans retour
              à la ligne final.  S'il est indiqué,  le  séparateur  est  placé
              entre chaque partie de la chaîne de version.

       --grep Filtrer  le fichier d'entrée vers le fichier de sortie.  Voir la
              section FONCTIONS MDGREP plus bas pour savoir comment piloter ce
              filtrage.

       --grep-showvars
              Afficher le nom et  la  valeur  de  chaque  variable  connue  de
              l'option grep.

       --grep-trace
              Activer  la trace de débogage de la fonction grep (il faut aussi
              indiquer --grep).

       --grep-defined symbole
              Sortir avec le code vrai du shell (0) si symbole  est  connu  et
              défini, sinon avec le code faux (1).

       --grep-define symbole
              Forcer  symbole  à  « défini ».  Symbole doit déjà être connu de
              makedefs.

       --grep-undef symbole
              Forcer symbole à « non défini ».  Symbole doit déjà  être  connu
              de makedefs.

FONCTIONS MDGREP
       La  commande  --grep  (et certaines autres commandes) filtre son entrée
       ligne par ligne, selon des lignes de contrôle placées dans l'entrée  et
       selon  des informations tirées de la configuration de NetHack(6).  Cela
       permet par exemple d'inclure dans les fichiers de documentation princi-
       paux des passages propres à une plate-forme.

       Règles :

              -   Au départ, l'état conditionnel est « affichage activé ».

              -   Une ligne qui ne commence PAS par un accent circonflexe  (^)
                  est  supprimée ou recopiée telle quelle, selon l'état condi-
                  tionnel en cours.

              -   Une ligne qui commence par un  accent  circonflexe  est  une
                  ligne  de  contrôle ; comme en C, on peut placer des espaces
                  presque partout dans la ligne  (sauf  juste  après  l'accent
                  circonflexe), mais l'accent circonflexe doit être en colonne
                  1.

              -   Les conditions peuvent être imbriquées.

              -   Makedefs  se  termine  avec  un code d'erreur si des erreurs
                  sont détectées ; le traitement continue (si  possible)  pour
                  en détecter le plus possible.

              -   Un  identifiant  inconnu  vaut à la fois VRAI et une erreur.
                  Remarquez que --undef ou #undef  dans  la  configuration  de
                  NetHack(6) ne sont pas la même chose qu'inconnu.

       Lignes de contrôle :

              ^^  une ligne qui commence par un accent circonflexe (un seul) à
                  prendre littéralement

              ^#  un commentaire

              ^?ID
                  si ID est défini, mettre l'état conditionnel à VRAI

              ^!ID
                  si ID n'est pas défini, mettre l'état conditionnel à VRAI

              ^:  sinon ; inverser l'état conditionnel

              ^.  fin de la dernière condition ouverte

ENVIRONNEMENT
       MAKEDEFS_LANG
              Propre  à  cette  version traduite.  Avec un code de langue (par
              exemple fr), les  commandes  qui  produisent  les  rumeurs,  les
              oracles,  les  épitaphes,  les  gravures, les noms hallucinés et
              l'encyclopédie lisent les fichiers traduits  nom-langue.txt  (ou
              .tru,  .fal,  .base) et écrivent nom.langue, que le jeu lit avec
              OPTIONS=language:langue.
